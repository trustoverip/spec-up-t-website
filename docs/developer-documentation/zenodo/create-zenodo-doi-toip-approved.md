# Create a Zenodo DOI – the ToIP way

:::info

Also see [the Spec-Up-T way](./create-zenodo-doi.md)

:::


This page describes how to assign a Zenodo DOI when a Spec-Up-T specification is being published as a [ToIP Approved Deliverable](https://lf-toip.atlassian.net/wiki/spaces/HOME/pages/767787009/ToIP+Approved+Deliverable+Process).

ToIP requires a persistent DOI for approved specifications so others can cite a stable, long-term version of the work. The technical workflow — reserve a DOI, embed it in the specification source, create a GitHub Release, upload the release archive to Zenodo, and publish the record — follows the same pattern as the general Spec-Up-T guide. See [Create a Zenodo DOI](./create-zenodo-doi.md) for the step-by-step instructions.

The ToIP process adds a few requirements on top of that workflow:

- **Reserve the DOI before release** — the DOI must appear in the specification before the official version is published, so the released artifact itself is citable.
- **Include a web-rendered link in Zenodo metadata** — if the specification is published on GitHub Pages or another public site, add that URL to the Description field of the Zenodo record.
- **Submit to the ToIP Zenodo community** — after publishing, submit the record to the [TrustoverIP community on Zenodo](https://zenodo.org/communities/trustoverip/) so it appears in ToIP's collection of publications.
- **Notify the Steering Committee** — after submitting the community request, notify the ToIP Steering Committee so the request can be accepted and the deliverable status can be updated.

For the full governance context — including when a specification becomes a ToIP Approved Deliverable and how that fits into ToIP's lifecycle — refer to the official [ToIP Approved Deliverable Process](https://lf-toip.atlassian.net/wiki/spaces/HOME/pages/767787009/ToIP+Approved+Deliverable+Process).
